## **2. 技术栈**

### **2.1 核心框架**



* **Gameplay Ability System（GAS）**：支撑游戏能力激活、效果叠加、属性修改的核心系统，是整个战斗逻辑的基础。

* **Unreal Networking**：虚幻原生网络框架，通过属性同步、RPC 通信、混合复制模式，保障多人游戏的状态一致性与稳定性。

### **2.2 架构设计**



* **MVC 模式**：严格分离 UI 视图（View）、业务逻辑（Controller）、数据模型（Model），降低模块耦合，便于后期迭代。

* **模块化设计**：按功能拆分「能力系统」「网络同步」「AI 逻辑」「UI 交互」等独立模块，支持单独拓展或替换。

* **单例模式**：统一管理全局资源（如 GameplayTag、配置数据），避免重复创建与硬编码，提升开发效率。

* **数据驱动**：通过可视化配置文件（DataAsset、DataTable 等）控制游戏数值与逻辑，无需修改代码即可调整参数。

### **2.3 数据管理**



* **DataAsset**：存储角色基础属性（血量、攻击力）、技能配置（伤害类型、伤害）等结构化数据，支持单独导出 / 修改。

* **DataTable**：管理批量数据，如 UI 反馈文本（伤害飘字、技能提示）、角色成长参数（每级属性增量），便于批量维护。

* **Curve Table**：通过曲线定义动态数值关系，如「等级 - 血量成长曲线」「技能伤害 - 距离衰减曲线」，可视化调整数值平衡。

* **GameplayTag**：标准化标记系统，关联「能力激活条件」「UI 反馈触发」「状态判定」等逻辑，统一标签管理，避免命名混乱。

### **2.4 AI 系统**



* **行为树（Behavior Tree）**：可视化定义敌人智能行为流程，涵盖「巡逻→发现目标→追击→攻击→脱离仇恨」全链路逻辑。

* **黑板（Blackboard）**：动态存储 AI 实时状态参数，为行为树决策提供数据支撑。

### **2.5 UI 系统**



* **委托（Delegate）**：实现「属性变化→UI 自动更新」的联动，例如角色血量变化时，血条无需手动调用刷新，通过委托自动同步。

* **UMG（Unreal Motion Graphics）**：构建游戏全量界面，包括血条、技能栏、伤害飘字、弹窗提示等，支持动画过渡与交互逻辑。

* **数据绑定**：通过配置将 DataTable 数据与 UI 组件直接关联（如技能图标、冷却时间文本），可视化修改界面表现，无需代码干预。
